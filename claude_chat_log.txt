  What package-lock.json is

  package.json lists the packages you asked for, with loose version ranges.
  "axios": "^1.20.0" means "1.20.0 or any newer 1.x version."

  package-lock.json is a record npm writes itself. It lists every package that
  actually got installed, at its exact version. That includes the packages your
  packages depend on, and the packages those depend on. You never edit it by
  hand. Its job is to make every install identical.

  That matters for you because your deploy workflow runs npm ci, which installs
  exactly what the lockfile says. So GitHub builds with the same versions you
  tested with locally. Commit it whenever it changes.

  You can't fetch only some fields

  PokeAPI always returns the full object for a Pokémon. There's no option to
  request just certain fields. "Only what we need" happens on our side instead:

  takes one line in a button's click handler:
  new Audio(pokemon.cries.latest).play();
  The only catch is that older Safari can't play .ogg files. Chrome and Firefox
  can. I've included cries in the type so it's ready for when you want it.

  src/pokemonAPI.ts (new)
  import axios from 'axios';

  // Only the fields we use; the rest of the response is ignored.
  export interface Pokemon {
      abilities: { ability: { name: string } }[];
      base_experience: number;
      cries: { latest: string };
      height: number;
      id: number;
      name: string;
      stats: { base_stat: number; stat: { name: string } }[];
      types: { type: { name: string } }[];
      weight: number;
  }

  const api = axios.create({ baseURL: 'https://pokeapi.co/api/v2' });

  // Fetch one Pokémon by id or name.
  export async function getPokemon(id: string): Promise<Pokemon> {
      const response = await api.get<Pokemon>(`/pokemon/${id}`);
      return response.data;
  }
  - The interface describes the shape of the data. { ... }[] means "an array of
    these," which matches the nesting in the API response (for example
    types[0].type.name).
  - axios.create sets the base URL once, so later calls only need the path.
  - The <Pokemon> in api.get<Pokemon> tells TypeScript what response.data
    contains.
  - height is in decimetres and weight in hectograms, so Pikachu comes back as 4
    and 60. Convert them when you display them.

  src/pages/DetailView.tsx (updated)
  import { useEffect, useState } from 'react';
  import { useParams } from 'react-router-dom';
  import { getPokemon, type Pokemon } from '../pokemonAPI';

  // Single Pokémon view.
  function DetailView() {
      // Read the id from the /pokemon/:id route.
      const { id } = useParams();
      const [pokemon, setPokemon] = useState<Pokemon | null>(null);

      // Fetch whenever the id in the URL changes.
      useEffect(() => {
          if (id) {
              getPokemon(id).then(setPokemon);
          }
      }, [id]);

      if (!pokemon) {
          return <p>Loading...</p>;
      }

      return (
          <h2>#{pokemon.id} {pokemon.name}</h2>
      );
  }

  export default DetailView;
  - useState holds data the component displays. <Pokemon | null> means it's
    either a Pokémon or nothing yet. When setPokemon runs, React redraws the
    component.
  - useEffect runs code after the component renders. The [id] at the end tells
    React to re-run it only when id changes. That's what will make your
    prev/next buttons work: change the URL and the new Pokémon loads.
  - The first render shows "Loading..." until the request comes back.

  I've left out error handling, so a bad id like /pokemon/abc just stays on
